# Device session protocol v1

Use a UTF-8 line prefixed with the seven ASCII bytes `@micro ` and terminated by LF. The JSON object contains `"v":1,"id":"<1..32 ASCII alnum>","op":"..."`. Reply prefix and v/id are identical, plus `"ok":true,"data":...` or `"ok":false,"error":"..."`. Clients ignore echoes, unrelated IDs and ordinary text; embedded JSON strings escape LF. Exactly one result frame per accepted request. Limit an entire frame including LF to 4096 bytes. Reject oversize/incomplete input without partial execution and resync at newline. JSON can use nested values only as defined below. One outstanding request per connection. Caller controls timeout. An interrupted write/action after sending may have executed. No replay. An explicit remote error must not drive fallback to a second executor. A complete write or successful read is a local device operation, never an implicit delivery ACK.

- `catalog`: optional nonnegative `offset` and `limit` (default 16, max 64). Data object `{"items":[{"id":INTEGER,"key":["sensor","temperature",null],"instance":"journal:local","read":true,"write":false}],"more":false}`. Keys are unique in the published view. ID is positive and stable for that registration. Hidden entries are omitted. Limit encoded page to fit; more means offset + actual length. Fail if one entry exceeds budget.
- `read`: `key` triple, required integer `limit` (0..128); optional `begin`, `end`, `params`. Data is an array of flat document objects. Respect limit and supported selection, return an error on unsupported bounds/filters or a result too large; do not silently truncate. For journals simple unfiltered reads return oldest retained documents first. Exposed SQL uses its actual read semantics. Wire scalar supports JSON null, bool, number, string, and `{"$us":SIGNED_INT}` for typed UTC Unix microseconds where supported; use that representation in date bounds as well. A key triple is connector, metric, optional location (null for none).
- `write`: `key`, `rows` array of flat documents, max 128 rows within frame. Data is a user-readable success message. Return local sync failure info honestly including confirmed partial group counts if supplied by store. Pre-existing explicitly writable Pipe only; never create a new stream based on input.
- `actions`: Data array of canonical action names visible to this session.
- `complete`: `line` (current partial action string). Data array of visible matching canonical names.
- `action`: `line` string. Data is captured action output/message on success; `error` human output/message on failure. Raw interactive console retains normal human transcript; protocol calls apply explicit operation and per-action admission; e.g. help must not disclose hidden entries. No eval/shell escape.
- USB dedicated serial connection while service running (baud 115200 default; configurable). No injecting Python into a REPL. Device app decides which session rights an attached host has.
- BLE separate management GATT 128-bit service 2f725f70-9771-4f95-bb68-5e47ea680001; RX write-with-response ...0002; TX notify ...0003 (replace four final hex chars). Fragment by negotiated ATT payload and assemble LF-delimited frames; accept <=20-byte fragments by default on hosts where negotiation unavailable. Require encrypted authenticated bonded connections and an explicitly authorized peer on the device. Serialize one outstanding request. No changes to existing custody GATT or receipts.
