# Make MicroPython and its source plugins first-class

MicroPython and native ESP-IDF C/C++ are first-class authoring environments for device Pipes. In MicroPython, a trusted module selected by `plugin:<name>` supplies documents through `fetch(pipe, **kw)` and may supply registration defaults through `register(pipe, **kw)`. Authors can install a Python module on the device or freeze it in a firmware image. Native firmware can bind the same source name to a compiled function. Both environments can also push a batch directly. [Device API examples and qualification](../device-api.md)

Use a plain connector key such as `sensor` for a push-only example. The application supplies the frame to `Pipe("sensor", "temperature").sync(df)`. With `plugin:weather`, a bare `pipe.sync()` can call the configured source. Supplied data goes straight to the write path on either Pipe. The desktop plugin interface also has a custom `sync` hook for plugins that drive writes themselves and return the outcome. A device source only needs to implement `fetch` to produce rows. [Meerschaum plugin hooks](https://github.com/bmeares/Meerschaum/blob/v5.1.5/docs/zensical/reference/plugins/types-of-plugins.md)

For a locally stored Pipe, `pipe.sync()` fetches from the configured source and commits the resulting documents to the selected local target. `pipe.sync(df)` commits supplied data directly. Success promises local durability, including when the radio is offline. Delivery progress reports which custodian or destination has durably accepted the stream. The default target uses segments. The optional [SQLite instance](0010-offer-an-optional-on-device-sqlite-instance.md) also maintains queryable rows. [Accepted data shapes](0008-include-a-dictionary-to-pipe-path.md) · [Peer instance proposal](../peer-sync.md#where-does-a-pipe-live)

The MicroPython API uses the portable C journal and codec. A timing-sensitive driver can submit bytes from caller-owned buffers to the same core and use the same storage and delivery guarantees. This parallels the relationship between the standard Meerschaum Python API and its Rust kernel. [Meerschaum Python implementation](https://github.com/bmeares/Meerschaum/blob/v5.1.5/meerschaum/core/Pipe/_sync.py#L889-L899) · [Meerschaum source plugin conventions](https://github.com/bmeares/Meerschaum/blob/v5.1.5/docs/zensical/docs/python/plugins.md)

Preserve the familiar `success, message = pipe.sync(df)` result. If a call commits several groups and then fails, distinguish confirmed input progress from an uncertain final group. A row upsert count and a receiver receipt describe different outcomes. [Upstream behavior and device conformance](../meerschaum-design.md#what-to-carry-over)
