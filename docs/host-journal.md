# Host journal and direct peer exchange

The POSIX reference library runs two independently durable journals through the draft v1 exchange. Link `micromeerschaum_posix` in a host CMake build. Each private, already-created directory holds one stream in one role. Open an origin with its origin ID, exact Pipe key, generation and designated receiver. Open the peer with the same identity and destination in receiver mode. A mismatched scope fails on reopen, and an exclusive lock prevents simultaneous owners of a directory. Serialize calls on each open handle. [Journal API](../core/include/micromeerschaum/journal.h) · [Working example](../examples/host/sync.c)

1. **Collect offline.** `mm_journal_append_group` assigns consecutive sequences and commits a group to one segment. The payload can be sensor-specific bytes. A successful return allows the caller to reuse its buffers. Two calls with the same reading create two observations.
2. **Build and transport a batch.** Start `mm_peer_batch` at `mm_journal_confirmed(origin)`. Supply the buffer size and record-count budget. Every returned record is complete. If the next record cannot fit an empty batch, increase the budget. A zero record limit produces a receipt query. The application schedules all connections.
3. **Accept and confirm.** `mm_peer_receive` validates the authenticated immediate sender, configured stream, destination and records, then commits new bytes before returning a receipt. Out-of-order records are readable immediately. The receipt advances across the contiguous prefix, including ranges explicitly accounted for by a typed loss declaration. A count of never-admitted samples accounts for no sequence range. Identical repeats reuse saved bytes. A repeated identity with different bytes fails.
4. **Retire confirmed data.** `mm_peer_confirm` checks the authenticated issuer and receipt scope, then persists the sender's confirmed position. `mm_journal_reclaim` removes fully confirmed origin segments. The origin remembers the sequence floor even after the last segment is gone. A receiver keeps the original bytes. [Peer API](../core/include/micromeerschaum/peer.h) · [Receipt format](../spec/protocol-v1.md#receipt)

## Restart and storage errors

The journal writes a complete staging file, syncs it, publishes it by rename and syncs the directory. Reopening validates the manifest, segment names, checksums and record ranges, rebuilds coverage and cleans up an abandoned staging file. Published segments are immutable. The underlying local filesystem must support checked file and directory synchronization, atomic rename and exclusive locking. The owner is responsible for durable provisioning of the directory itself.

In the grouped transfer test, twelve readings use two storage sync calls at the origin and four at the receiving peer. The receiver publishes its observed route and grouped payload in two synced renames. Replaying the same batch on the open peer adds zero storage syncs. Persisting the sender's receipt and reclaiming data are separate operations. [Grouped transfer test](../core/tests/test_delivery.c)

A failed barrier can leave a commit's outcome uncertain. Close and reopen the handle before using it again. On uncertain local append, use the returned first sequence and original group to reconcile the stored bytes. On uncertain delivery, retry the same encoded records. A peer that committed before its reply went missing will recognize them. An error from receive supplies no receipt to send. The reference test exercises this by failing a directory sync after publication. [Recovery tests](../core/tests/test_delivery.c)

Give a stream generation exactly one origin allocator. Persist its directory across restarts. If the sequence authority is lost, provision a fresh generation before collecting again. Copying or restoring an old directory as a second writer for the same generation could reuse identities. Keep each manifest together with its segments when moving an archive. [Stream generation decision](adr/0006-identify-stream-generations.md)

The host port indexes segments in memory and can cache a segment of up to 1 MiB. A configured byte limit applies to stored segment bytes. A full journal reports the failure and protects its existing data. The bounded volume port adds automatic loss accounting and per-Pipe retention and can open the same file on a host or mounted device filesystem. [Bounded storage](device-storage.md) The receiver can be a final destination or a provisioned custodian. Authentication of the actual link belongs to the caller.
